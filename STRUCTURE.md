# Структура проекта

Актуально на 1 августа 2026 года.

Это статический сайт-путеводитель для Лиды и Андрея. У него нет сборки, сервера или менеджера пакетов: браузер загружает HTML, CSS и ES-модули напрямую. Для локального просмотра нужен обычный HTTP-сервер; открывать `index.html` через `file://` нельзя, потому что браузер заблокирует импорты модулей.

## Файлы

```text
index.html                 Каркас страницы: hero, две сетки карточек, модальное окно

css/
  base.css                 Переменные, шрифты, базовые стили и фон
  layout.css               Hero, секции и общая компоновка страницы
  components.css           Карточки маршрутов, кнопки, модальное окно
  timeline.css             Точки маршрута, транспорт, галереи и lightbox
  tailwind-fallback.css    Небольшой локальный набор классов на случай сбоя Tailwind CDN

data/
  index.js                 Импорты и массивы маршрутов Лиссабона и Порту
  routes/
    *.js                   По одному ES-модулю на маршрут

js/
  app.js                   Рендер карточек и модального окна, галереи, карта, deep links
  transit.js               Переходы между точками и ссылки на Google Maps
  utils.js                 Экранирование HTML, timeout запросов, кэш галерей
```

## Что где меняется

Чтобы добавить маршрут, создайте файл рядом с остальными, задайте уникальный числовой `id` и добавьте импорт в `data/index.js`. Маршруты Лиссабона идут в `routes`, дальние выезды — в `getawayRoutes`, маршруты Порту — в `portoRoutes`. Пока `ready: true`, карточка появится на сайте. Для отложенной заготовки ставьте `ready: false`.

Не переносите данные обратно в `index.html`: его карточки нужны только как начальная разметка до загрузки модуля, затем `app.js` заменяет их данными из `data/`.

### Интерфейс

`index.html` содержит всю постоянную разметку страницы и подключает стили с `js/app.js`. `app.js` отвечает за:

- сетки карточек Лиссабона, дальних выездов и Порту;
- модальное окно маршрута и ссылку вида `#route=<id>`;
- ленивую загрузку Leaflet-карты;
- галереи точек, их кэш в `localStorage` на семь дней и запасные изображения;
- полноэкранный просмотр галереи, клавиши стрелок и Escape;
- ссылки на пешие и транспортные переходы в Google Maps;
- проверку и повторную загрузку удалённых картинок с корректным `referrerpolicy`.

Если задача касается только транспорта, правьте `js/transit.js`. Общие безопасные функции и кэш находятся в `js/utils.js`. Не добавляйте новую логику в файл данных маршрута.

### Стили

Стили разделены по ответственности, а не по каждой мелкой детали. Для карточки ищите правило в `components.css`, для секции или hero — в `layout.css`, для модального маршрута и галереи — в `timeline.css`. `tailwind-fallback.css` не заменяет дизайн сайта: это страховка для небольшого набора utility-классов, которые обычно даёт подключённый Tailwind CDN.

## Внешние сервисы

Сайт зависит от сети для шрифтов Google Fonts, Tailwind CDN, Leaflet, тайлов CARTO, изображений Wikimedia Commons и ссылок Google Maps. Карта Leaflet загружается только после открытия маршрута. Галереи сначала используют явно заданные файлы, затем категории и поиск Commons; результаты кэшируются локально. Для Wikimedia есть запасная загрузка через `wsrv.nl`.

В коде уже есть версии в query-параметрах у некоторых CSS- и JS-файлов. Меняйте их только после правки соответствующего ресурса, когда нужно обойти кэш браузера.

## Проверка перед публикацией

Автоматических тестов и сборки в репозитории нет. После изменения откройте сайт через локальный HTTP-сервер и проверьте вручную:

1. главную страницу и обе сетки карточек;
2. открытие каждого изменённого маршрута;
3. карту, точки и ссылки Maps;
4. галереи, навигацию lightbox и запасное изображение;
5. прямую ссылку `#route=<id>` и закрытие по Escape;
6. мобильную ширину экрана.

## Публикация

Удалённый репозиторий: `https://github.com/mrbassvilleport/LIda_Andrey.git`. В самом репозитории нет workflow или файла настройки GitHub Pages, поэтому способ публикации задан в настройках репозитория на GitHub. Для сайта, настроенного на ветку `main`, обычная последовательность такая: проверить изменения, сделать коммит и отправить `main` в `origin`. После этого GitHub Pages подхватит новую версию по своей конфигурации.

Перед отправкой всегда смотрите `git status`: в репозитории могут быть чужие незавершённые изменения. Не добавляйте React, Vite или другой этап сборки без отдельной причины: для этой структуры нативных модулей браузера достаточно.
